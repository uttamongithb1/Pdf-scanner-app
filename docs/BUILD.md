# Build and run

## What is checked in

This is a working development implementation, not just wireframes. It includes a Flutter UI, Kotlin Android engine, Swift iOS engine, SQLite persistence, platform projects, tests and CI definitions. It is not a store-qualified release.

- Flutter **3.35.7** / Dart **3.9.x** is the CI baseline.
- Android minimum **API 26**, Java **17**, Android SDK/NDK versions provided by Flutter's build tooling.
- iOS minimum **16.0**, Xcode on a Mac and CocoaPods.
- Provisional bundle/application ID: `com.lumen.pdfscanner`. Change it before store registration if you do not own/use this namespace.

## Local setup

Install Flutter and the platform toolchains, then:

```sh
flutter doctor -v
flutter pub get
flutter analyze
flutter test
flutter run
```

Use a physical phone for scanning. iOS simulators do not provide VisionKit document capture. Android needs compatible Google Play services for the automatic scanner; its initial components may need downloading. **Camera · manual crop** and photo import are independent fallback choices.

Do **not** run `flutter create .` over the repository: full platform projects and custom native integration are already checked in.

Dependency lockfiles are generated by real CI package resolution, never fabricated. `pubspec.lock` and `ios/Podfile.lock` pin the reviewed application dependency graph. CI uses `flutter pub get --enforce-lockfile`; intentional upgrades must update the locks and repeat native builds. See [build status](BUILD_STATUS.md) for provenance and validated source revisions.

### This Arena workspace

```sh
source scripts/workspace_env.sh
./scripts/check_toolchain.sh
```

The environment helper exposes tools under `.cache` and respects externally supplied Flutter/Android/JAVA_HOME settings. Cache files are not committed and may need reinstalling in a fresh workspace. The capability checker intentionally fails if the full toolchain is missing.

This Linux workspace currently has Python PDF/parser and Dart-formatting tools, but **not** a runnable Flutter/Dart binary SDK, full JDK, Android SDK/adb or Xcode. Earlier test-only Java/Kotlin tools and a Flutter source checkout were cached during build investigation; those caches are ephemeral and must not be assumed present. Download attempts to `storage.googleapis.com`, `pub.dev`, `dl.google.com`, and `services.gradle.org` fail under the workspace network policy. Temurin JDK downloads redirect to a blocked GitHub asset host as well. A source checkout alone cannot run Flutter.

Actual mobile builds run on GitHub-hosted Linux/macOS runners, which install the required SDKs. The reported Android emulator and iPhone simulator integration runs are remote, not local or physical-device runs. Normal GitHub Actions artifact downloads also redirect to a blocked blob host **from this workspace**; open the artifact links in your browser instead. The public dependency locks can be retrieved over GitHub's check-annotation API:

```sh
# Run while HEAD matches the CI source revision. Requires authenticated gh.
python3 scripts/ci_lockfiles.py fetch <run-id>
```

This helper transfers only the two allowlisted public lockfiles, checks chunk completeness and SHA-256, and refuses to overwrite a different existing file. It never exports credentials or signing files.

## Android

```sh
flutter devices
flutter run -d <android-device-id>
flutter build apk --debug
LUMEN_ALLOW_DEBUG_SIGNING=true flutter build apk --release  # INTERNAL TESTING ONLY
```

Open Settings → Library location and select a local folder. The app creates `PDF Scanner` below the selected directory unless it is already selected. Subfolders are `PDFs`, `Images/Processed`, and optionally `Images/Originals`.

If you decline, exports use app-specific storage, clearly labelled **App storage**. It is not guaranteed visible through a third-party file manager and is removed at uninstall. Use Share to save an independent copy.

**Release signing fails closed.** Without private signing configuration, a normal `flutter build apk --release` must fail. CI verifies that failure before building its explicitly opted-in, debug-signed `android-release-development-apk`. Never publish that development artifact.

For distribution, create a protected upload keystore outside Git and supply ignored `android/key.properties`:

```properties
storeFile=/absolute/path/to/private-upload.jks
storePassword=YOUR_LOCAL_SECRET
keyAlias=YOUR_UPLOAD_ALIAS
keyPassword=YOUR_LOCAL_SECRET
```

Use your own local values, never commit this file or share secrets in chat. With it configured, run `flutter build appbundle --release` and verify the signing certificate before upload. Keep backups of the protected key; a CI development key is not your production identity.

## iOS

```sh
flutter pub get
cd ios && pod install && cd ..
open ios/Runner.xcworkspace
flutter run -d <iphone-device-id>
```

For compilation without an Apple signing account:

```sh
flutter build ios --simulator --debug
flutter build ios --release --no-codesign
```

CI archives the simulator app as a tarball to preserve executable permissions and framework symlinks. It runs on a compatible Mac simulator, **not** an iPhone. An unsigned device release build cannot be installed on an iPhone or submitted to the App Store.

Select your signing team in Xcode. PDFs and saved images appear in **Files → On My iPhone → PDF Scanner** (the iPad equivalent uses On My iPad). iOS cannot create a global filesystem folder like Android. The Change/Files destination control reports the app container; use Share to export copies elsewhere. Arbitrary canonical external-library bookmarks are not implemented on iOS.

## Checks

```sh
python3 scripts/check_repository.py
flutter analyze
flutter test --coverage
flutter build apk --debug
flutter build ios --simulator --debug  # macOS only
```

`.github/workflows/mobile.yml` executes Flutter analysis/tests, repository and asset regression checks, Android debug/optimized APK builds, iOS simulator/unsigned-device builds, the pure-JVM PDF writer smoke test, native Android/iPhone-simulator integration tests, a negative signing-guard test and sampled Android emulator memory reporting. Actual run results and artifact links are recorded in [BUILD_STATUS.md](BUILD_STATUS.md).

To rebuild the current work branch without changing main:

```sh
gh workflow run mobile.yml --ref arena/dd30c98a-pdf-scanner-app
gh run list --branch arena/dd30c98a-pdf-scanner-app
# Then watch the selected run, and download its artifacts on an unrestricted machine:
gh run watch <run-id> --exit-status
gh run download <run-id> --name android-release-development-apk
```

Optional local syntax parser:

```sh
python3 -m pip install tree-sitter tree-sitter-dart tree-sitter-kotlin tree-sitter-swift
python3 scripts/syntax_check.py
```

Pure-JVM PDF output check (no Android SDK needed):

```sh
# Have Java 17 and Kotlin 2.1 available; use KOTLINC/JAVA environment overrides if needed.
python3 -m pip install Pillow PyMuPDF
python3 scripts/pdf_smoke.py
```

PyMuPDF is a test-only independent parser/renderer; it is not an app runtime dependency or bundled SDK. Review its licence if you repurpose that test dependency for distribution.

## Native integration and memory sampling

On a connected emulator/device (iOS requires a Mac):

```sh
flutter test integration_test/native_flow_test.dart -d <device-id> --reporter expanded --fail-fast
# Android emulator with adb on PATH:
python3 scripts/profile_android_integration.py
```

The tests cover synthetic image staging, filters, exact right-angle dimensions, invalid crops, PDF render/rename/delete, a fifty-page export with a real SQLite rollback/retry, corrupt-batch rollback and conservative preview cleanup. Android also simulates persisted rename/partial-delete crash windows; that platform-specific case is **skipped**, not counted as an iOS pass.

`android-native-memory-report` contains `build/reports/android-native-memory.json`: whole-app PSS/RSS sampled every two seconds in an **emulator/debug** build. Maximum sampled memory is not a guaranteed peak, does not include hosted scanner processes and does not qualify physical-device release performance. Execute the device plan separately.
