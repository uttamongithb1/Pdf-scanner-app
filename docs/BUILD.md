# Build and run

## What is checked in

This is an initial mobile implementation, not just wireframes. It includes a Flutter UI, Kotlin Android engine, Swift iOS engine, SQLite persistence, platform projects, tests and CI definitions. It is not a store-qualified release.

- Flutter **3.35.7** / Dart **3.9.x** is the CI baseline.
- Android minimum **API 26**, Java **17**, Android SDK/NDK versions provided by Flutter's build tooling.
- iOS minimum **16.0**, Xcode on a Mac and CocoaPods.
- Provisional bundle/application ID: `com.lumen.pdfscanner`. Change it before store registration if you do not own/use this namespace.

## Local setup

Install Flutter and the platform toolchains, then:

```sh
flutter doctor -v
flutter pub get
flutter analyze
flutter test
flutter run
```

Use a physical phone for scanning. iOS simulators do not provide VisionKit document capture. Android needs compatible Google Play services for the automatic scanner; its initial components may need downloading. **Camera · manual crop** and photo import are independent fallback choices.

Do **not** run `flutter create .` over the repository: full platform projects and custom native integration are already checked in.

The application lockfile should be generated by the first successful `flutter pub get`, reviewed and committed. It is not fabricated here because package resolution cannot be performed in the restricted build workspace. Dependency ranges are therefore not yet a reproducible resolved graph.

## Android

```sh
flutter devices
flutter run -d <android-device-id>
flutter build apk --debug
```

Open Settings → Library location and select a local folder. The app creates `PDF Scanner` below the selected directory unless it is already selected. Subfolders are `PDFs`, `Images/Processed`, and optionally `Images/Originals`.

If you decline, exports use app-specific storage, clearly labelled **App storage**. It is not guaranteed visible through a third-party file manager and is removed at uninstall. Use Share to save an independent copy.

The release build currently uses the template's debug signing configuration for development only. Configure a private upload keystore and secure release signing before producing a Play AAB. Never publish a debug-signed build or put signing credentials in Git.

## iOS

```sh
flutter pub get
cd ios && pod install && cd ..
open ios/Runner.xcworkspace
flutter run -d <iphone-device-id>
```

Select your signing team in Xcode. PDFs and saved images appear in **Files → On My iPhone → PDF Scanner** (the iPad equivalent uses On My iPad). iOS cannot create a global filesystem folder like Android. The Change/Files destination control reports the app container; use Share to export copies elsewhere. Arbitrary canonical external-library bookmarks are not implemented on iOS.

## Checks

```sh
python3 scripts/check_repository.py
flutter analyze --no-fatal-infos
flutter test --coverage
flutter build apk --debug
flutter build ios --simulator --debug  # macOS only
```

`.github/workflows/mobile.yml` defines those Flutter builds/tests plus the pure-JVM PDF writer smoke test. The workflow has not been dispatched from this workspace. A checked-in workflow is not evidence of a passing CI run.

Optional local syntax parser:

```sh
python3 -m pip install tree-sitter tree-sitter-dart tree-sitter-kotlin tree-sitter-swift
python3 scripts/syntax_check.py
```

Pure-JVM PDF output check (no Android SDK needed):

```sh
# Have Java 17 and Kotlin 2.1 available; use KOTLINC/JAVA environment overrides if needed.
python3 -m pip install Pillow PyMuPDF
python3 scripts/pdf_smoke.py
```

PyMuPDF is a test-only independent parser/renderer; it is not an app runtime dependency or bundled SDK. Review its licence if you repurpose that test dependency for distribution.
